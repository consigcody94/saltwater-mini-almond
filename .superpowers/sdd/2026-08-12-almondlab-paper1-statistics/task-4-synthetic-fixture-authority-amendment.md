Unknown, missing, reordered, duplicate, merged, or aliased keys fail. Every
nested mapping also uses the literal order shown in the normative payloads.
The schema is a discriminated, strict union only at
`calibration_registration`: it is either literal `null` or the exact C2
registration object shown in `known_effect.yaml`. No other candidate or
calibration object is accepted at version 1.0.0.

Primitive rules are exact:

- strings, booleans, integers, floats, arrays, maps, and `null` must retain
  their YAML primitive type; a boolean is never an integer;
- every displayed decimal is a finite exact Python `float`; counts and seeds
  are exact Python `int` values;
- hash values are lowercase 64-character hexadecimal strings;
- `candidate_order` is exactly `C1` through `C6` in registry order;
- each mechanism record has exactly `candidate_id`, `mechanism_role`,
  `template_source`, `parameters`, `template_reference`,
  `requires_calibration_resolution`, and `evidence_label`, in that order;
- exactly one of `parameters` and `template_reference` is non-null;
- a non-null parameter map has the exact two Task 2 isolation keys for its
  candidate, in the order printed below; and
- `mechanism_role` is only `equal_null`, `calibration_target`, or
  `hypothesized_useful`. The last is a synthetic design role, not a finding.

Primitive exactness applies to the parsed YAML graph before typed
construction. During detached model construction, evidence strings alone are
converted to the corresponding exact `EvidenceLabel` members shown in Section
4.3; because `EvidenceLabel` is a string enum, canonical JSON bytes remain the

## 9. Confirmation and calibration fail-closed contract

Parsing and canonical validation of a registration template are read-only and
may succeed after this fixture authority is approved. Generation is a
separate boundary.

Any request for confirmation generation or tournament assembly sees
`generation_binding.confirmation.authority_state == registration_required`
and must raise, before reading candidate family inputs:

```text
code: CONFIRMATION_DESIGN_REGISTRATION_REQUIRED
field_path: confirmation_design

details.required_authority: task4_registered_confirmation_cohort_bundle
```

The details map has exactly the one displayed key. Null confirmation fields
must remain null. A zero seed, empty array, all-zero digest, discovery hash,
copied test confirmation object, or a structurally valid same-count family is
not a substitute.

For `known_effect`, any cohort generation attempted without a separately
returned and canonically revalidated calibration result raises:

```text
code: CALIBRATION_RESULT_REQUIRED
field_path: calibration_registration
message: known-effect generation requires a separately validated mechanism calibration
details.required_candidate_id: C2
```

The loader itself never raises that generation error and never invokes the
solver. It returns only an authenticated envelope around a typed registration
template and its immutable source bytes/digests; it returns no generated
truth. A future calibration result must match C2, the target, bracket, solver
version, tolerances, and both K64 hashes, but its fitted value and realized

## 10. Exact loader and error contract

The prospective public loader and its mandatory consumer revalidator are:


There is no overload without `authorities`, no digest argument, and no public
path-only or bytes-only shortcut. The authority carrier is keyword-only. The
loader performs this exact phase order before any RNG, solver, package write,
or run-directory creation:

   131,073 bytes from a binary stream; an empty or larger file fails without
